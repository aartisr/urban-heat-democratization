# City Page Pattern Synthesis

This note captures the design direction for a generic bundled-city page in Urban Heat Democratization.

## Goal

Create a city page that can work for:

- bundled real-data cities,
- upload-first cities,
- educator and student study flows,
- planner and researcher decision workflows.

The page should feel:

- map-first,
- evidence-aware,
- action-oriented,
- modular enough to reuse for any city.

## Pattern Synthesis

The strongest comparable civic-analysis products consistently use these patterns:

1. Start with one clear city promise instead of many competing summaries.
2. Put the map early so users orient spatially before reading analysis.
3. Use progressive disclosure: overview first, deeper evidence later.
4. Keep trust language near the insight, not buried in a footer.
5. Offer only a few primary actions at the top.
6. Convert analysis into a natural next step instead of forcing users to guess.
7. Attach selected-map context directly to planning actions.
8. Use small metric clusters instead of long tables at the top.
9. Distinguish observed, derived, estimated, and illustrative content clearly.
10. Preserve one generic layout while swapping content by city readiness and package availability.

## Resulting Layout Standard

The bundled-city page should follow this order:

1. Hero
2. Three-step journey
3. Map and overlays
4. Why this matters / natural next step
5. Evidence and honesty
6. Snapshot and actions
7. Guided study workflow
8. Readiness or local data registration
9. Robustness context

## Why This Works

- New users get orientation quickly.
- Expert users still have access to evidence and provenance.
- The page stays concise because each section answers one question.
- The same structure can scale from Boston to any future bundled city.
