# Repository Capability Status

Created by [Aarti S Ravikumar](https://ai-aarti.com/) for [Urban Heat Democratization](https://urban-heat.ai-aarti.com/).

This is a concise status record for readers checking what the public application can support. Start with the [documentation guide](README.md), [Boston study guide](BOSTON_STUDY_GUIDE.md), and [research wiki](wiki/README.md).

## Available now

- A web application and API for city evidence, exploratory scenarios, runs, exports, and research methods.
- A bundled Boston study boundary and documented local overlays for inspection. Other city presets are onboarding starting points rather than completed local studies.
- Graph, spectral, conductance, reliability, percolation, and raster methods with source code and tests. Their results describe a model built from stated inputs and assumptions.
- A mitigation lab with a bounded browser priority field and a separate teaching-graph analysis. The browser field is not a temperature forecast.
- Canonical page metadata, sitemaps, citation information, author attribution, and a static research companion.

## Important limits

- Scenario costs and benefits are exploratory and partly benchmark-derived. The site does not provide validated city-specific engineering, temperature, health, or equity forecasts.
- A graph bottleneck or modeled cooling-access constraint is a prompt for local investigation, not a measured outcome for a person or neighborhood.
- Address-level planning remains a starting checklist. Immediate heat-safety decisions should use current local public-health guidance.
- The current application stylesheet exceeds its 220 KiB CI performance budget. The performance gate needs a separate reduction.

For claims that an intervention changed heat, follow the [impact evidence protocol](IMPACT_EVIDENCE_PROTOCOL.md). For software attribution, use [CITATION.cff](../CITATION.cff).
